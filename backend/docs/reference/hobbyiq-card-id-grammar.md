# The `hiq:` identity grammar

The canonical HobbyIQ card identifier. Vendor-independent, deterministic,
human-readable — one card, one slug, one comp pool.

Generated by `computeHobbyIqCardId` and read back by `parseHobbyIqCardId`, both
in `backend/src/services/portfolioiq/hobbyIqCardId.service.ts`. That file is the
authority; this page is the grammar it implements, written down so a reader does
not have to reconstruct it from 1,900 lines of normalization rules.

## The grammar

```
hiq:{sport}:{year}:{setKey}[:sub-{subsetSlug}]:{cardNumber}:{parallelSlug}:{autoFlag}[:num-{printRun}]
```

Six required segments after `hiq:`, and two optional ones. The optional
segments are identified by their **prefixes**, never by counting fields — a
slug of eight segments may carry either one.

| segment | required | normalization |
| --- | --- | --- |
| `sport` | yes | lowercase, ASCII, no spaces. The top-level namespace, so card numbers cannot collide across sports. |
| `year` | yes | 4-digit integer. A split season ("2000-01") takes the **first** year. |
| `setKey` | yes | the shortest canonical name from the controlled vocabulary (`normalizeSetKey`, `resolveSetKeyForSlug`). |
| `sub-{subsetSlug}` | **only on a clash** | see below. |
| `cardNumber` | yes | lowercase, literal (letters, digits, hyphens). `player-{slug}` for a genuinely unnumbered card. |
| `parallelSlug` | yes | the slug of the **specific** variant, never a lossy label. `base` for the plain card. |
| `autoFlag` | yes | `auto` or `no-auto`. Never omitted — the absence of an autograph is a fact about the card, not a missing field. |
| `num-{printRun}` | only when numbered | omitted when the card carries no serial. |

### Examples

```
hiq:baseball:2026:bowman:cpa-eha:gold-refractor:auto:num-50
hiq:baseball:2026:bowman-chrome:bcp-102:orange-shimmer-refractor:no-auto
hiq:basketball:2024:panini-prizm:1:silver-prizm:no-auto:num-99
hiq:pokemon:2023:sv1:151:full-art:no-auto
hiq:basketball:2000:topps-chrome:sub-cards-that-never-were:mj1:refractor:no-auto
hiq:basketball:2000:topps-chrome:sub-johnson-reprints:mj1:refractor:no-auto
```

The last two are the same product, the same card number, the same rung — and
two different cards.

## The subset segment

**CF-A-SUBSET-IS-PART-OF-THE-IDENTITY-WHEN-IT-HAS-TO-BE** (Drew ruling,
2026-09-04).

### The defect

The slug had no subset axis. One product can publish two subsets that number
their cards alike, and those cards then shared one slug — one comp pool holding
two different cards, which is the split-pool failure inverted.

Measured, not hypothesised (#1741): **2000-01 Topps Chrome** publishes both
*Cards That Never Were* (MJ1–MJ10) and *Johnson Reprints* (MJ1–MJ7). Every row
is Magic Johnson; both are Refractors. Reparenting both onto `topps-chrome` —
which is where they belong — put MJ1 twice.

\#1741 stopped the merge by **refusing** the second write and counting it. That
was right about the harm and left those cards uningestable.

### The ruling

For those cards, and **only** those cards, the subset becomes part of the
identity and each gets its own pool. Everything else is unchanged: a card whose
number is unique within its product gets no subset segment, so every slug
already in the catalog keeps the shape it has.

This is not a new axis on every card. It is a disambiguator applied exactly
where the product forced a collision.

### When the segment appears

`computeHobbyIqCardId` emits `:sub-{slug}` when, and only when, the caller
passes `subsetInId: true`. Everything else about that decision happens
upstream:

1. **The decision is the catalog's.** `subsetInId` is computed at ingest by
   asking whether the checklist for this `(year, setKey)` lists this
   `cardNumber` under more than one subset **at this rung** — the whole
   identity minus the subset. It is then **persisted on the catalog row**, so a
   later reader reaches the same slug without re-deriving the clash.

2. **It is never inferred from a title.** A clash is a fact about a whole
   product; one row cannot see it and a sale title certainly cannot. A matcher
   that read "Aptitude for Altitude" out of a title and appended it would mint a
   subset-bearing id for a card that has no clash — fragmenting a pool to fix a
   collision that was never there.

3. **Blank means unknown.** A row flagged `subsetInId` whose `subsetName` is
   blank is **refused** — `computeHobbyIqCardId` throws. Minting it without the
   segment would put it back on the plain id, the very address the clash makes
   ambiguous. \#1741's refusal counter survives for exactly this case.

### Why `sub-`, and why after the setKey

The segment reads *product > subset > card*, which is how the checklist itself
is organised. The `sub-` prefix makes it self-describing, so `parseHobbyIqCardId`
can tell an 8-segment slug carrying a subset from one carrying a print run
without counting fields — the same reason `printRun` carries `num-`.

**Positional slug parsing is now a bug.** Code that read
`slug.split(":")[5]` for the parallel gets a card number on a subset-bearing
slug. Use `parseHobbyIqCardId`. `deriveCatalogEntry` was fixed for this in the
same change.

## The matcher rule

`backend/src/services/catalog/subsetIdentity.ts`, mirrored for the rematch in
`backend/scripts/lib/subset-identity.cjs` (pure, so the classifier and the
invariant auditor need no build step; one pin drives both copies).

- A sale title that **names** one of the clashing subsets derives that subset's
  id.
- A title that names **none** of them derives the plain id and the rematch
  classifies it **`UNDERIVABLE-for-subset`** — report-only, never moved.
- A title naming **two or more** is likewise `UNDERIVABLE-for-subset`. There is
  no "best" candidate: either the seller said which, or they did not.

The match is a **whole-phrase, word-boundary** match on the folded text — not a
token overlap and not a fuzzy score. Subset names like "Base Set" and "Promos"
share tokens with half the corpus, and a partial match would assign cards by
coincidence.

**The refusal is the point.** \#1741 measured the market's own answer for the
motivating case: all three `sold_comps` rows carrying "Johnson Reprints" spell
the card #2 or #7, and the rest of the pool names no subset at all. Most sales
genuinely cannot be assigned, and a matcher that picked the larger subset would
file a card into a pool it may not belong to. An unassigned row stays exactly
where it is and is reported.

## Census, 2026-09-04

Read-only over `card_catalog` (`backend/scripts/census-subset-clash.cjs`).

| | |
| --- | --- |
| catalog rows carrying a `subsetName` | 1,479,447 |
| distinct rungs carrying a subset | 1,328,986 |
| **clash sets** (one rung under >1 subset) | **17** |
| products holding a clash set | 4 |
| distinct catalog slugs in a clash | 52 |
| **`sold_comps` rows on those plain ids** | **0** |

| product | clash sets | the two subsets |
| --- | --- | --- |
| `baseball 2020 panini-prizm-draft-picks` | 12 | "Base Auto Parallels Set" vs "Thunderstruck Auto Parallels Set" |
| `baseball 1957 topps` | 2 | "Base Set" vs "Promos" |
| `baseball 1962 topps` | 2 | "Base Set" vs "Promos" |
| `baseball 1997 leaf` | 1 | "Inserts" vs "Game-Used" |

**The motivating case is not in that table, and its absence is the finding.**
2000-01 Topps Chrome holds *Cards That Never Were* MJ1–MJ10 but **no** *Johnson
Reprints* rows at all — #1741's counter refused every one of them, so the clash
never reached the catalog to be measured. The 17 above are the clashes that
predate that guard; the refused population is larger and is only visible in an
ingest run's banner.

Zero pool rows sit on the 52 affected plain ids, so nothing needs relocating
today. That number is a snapshot: it will not stay zero once the refused
checklists land.

### Why the census is shaped the way it is

`GROUP BY` over `card_catalog` does not return. Measured 2026-09-04:
`GROUP BY c.subsetName` scoped to **one** product ran past 200s and returned
nothing. A **range** predicate on `subsetName` is index-served and returns the
whole subset-bearing population in ~73s for 68k RU, so the grouping is done
client-side on the rows that come back — the same shape as
`census-split-identity.cjs`, and for the same reason: an indexed predicate
server-side, the comparison in process.
