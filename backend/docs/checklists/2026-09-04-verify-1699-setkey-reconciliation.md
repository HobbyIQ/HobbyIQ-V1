## FINDING 1 — the headline recovery number is not reproducible

`measure-rematch.cjs` as committed, run against my census with a genuine
pre-change baseline, yields **40,469 rows across 74 cells** — not the 161,890
(140,319 keyRewrite + 21,571 era) the PR claims.

Every non-Donruss cell reproduces **exactly**: `basketball|2025|panini-select`
10,465, `baseball|1960|fleer` 5,347, `baseball|1996|score-select` 1,451. Every
discrepancy is a `panini-donruss` era cell.

The cause: the committed report shows `baseball|1987|panini-donruss` landing on
bare `donruss` for 16,306 rows, but the committed script never calls
`spellSetKeyForEra`, and `normalizeSetKey` does not do era rewriting. Re-running
with the era rule applied to the destination side reproduces the shape
(157,340 / 81 cells), confirming the report was generated by a step not in the
committed script.

**And that era step is not this PR's to claim.** `spellForEra` already exists in
`productSetKeys.ts` with live call sites, and on **pristine main**:

```
resolveSetKeyForSlug("baseball","Donruss",1987) -> donruss   (MAIN and BRANCH)
spellForEra("panini-donruss",1987)              -> donruss   (MAIN and BRANCH)
```

The Donruss era recovery was already available before this PR. The new
`spellSetKeyForEra` export has **zero production call sites** — only tests
reference it.

**What this PR actually recovers by key rewrite: ~40,469 rows.** The doctrine,
the fixed points and the un-fusion are the real deliverable; the recovery
headline is roughly 4x overstated.

## FINDING 2 — `manualIdentityPricing.test.ts` is a real red, not a chronic one

The PR reports this file as failing "identically on pristine main". It does not.

```
pristine main  (rebuilt, in isolation) : 3 passed
branch         (in isolation)          : 3 FAILED
branch + origin/main merged            : 3 FAILED
```

Root cause, from the failure output:

```
Error: setkey-reconciliation.json not found in any candidate path.
  Last error: ... missing entries/totals
 loadReconciliation src/services/catalog/setKeyReconciliation.ts:110
 src/services/catalog/setKeyReconciliation.ts:113   <- const DOC = loadReconciliation()
 src/services/portfolioiq/hobbyIqCardId.service.ts:46
```

The test stubs `fs.readFileSync` for its own fixture. `setKeyReconciliation.ts`
loads **eagerly at module top level and throws**, so any module graph that
reaches `normalizeSetKey` under an `fs` stub dies at import.

The established pattern in this repo is the opposite — `bowmanParallelsDataset.ts`
loads **lazily, caches, and falls back to `EMPTY_DATASET`**. Fix direction: make
`DOC` lazy behind a memoised getter so the read happens on first use rather than
at import.

Blast radius is bounded: 2 test files stub `fs`; only `manualIdentityPricing`
(3 tests) goes red, deterministically. **Production is unaffected** — with the
file present the candidate paths resolve, and `copy-static-data-to-dist` is
correctly extended, verified by `copied 3 file(s)`.
