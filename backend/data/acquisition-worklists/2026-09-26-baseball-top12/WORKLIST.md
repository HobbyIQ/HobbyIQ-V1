## 2026-09-26 classifier fix — regenerated with two defect fixes

PR #2439 review found two live classifier defects, both fixed in this
regeneration (`backend/scripts/acquisition-worklist.cjs`):

1. **Sibling-cell lazy load (defect 1).** `resolveDefectOrAcquire`'s sibling
   probe called `io.getCellIndex(cell.year, siblingKey)`, which only ever
   read whatever the main FOR loop had already `loadCatalogCell`'d for an
   EARLIER cell in `--setkeys`/`--cells-from` order — e.g. `2026:bowman-chrome`
   processed before `2026:bowman` meant every bowman-chrome sale's sibling
   probe of `bowman` saw an empty cache and fell through to ACQUIRE, even
   though the card was live and checklist-backed under the sibling key. Fixed
   by extracting `resolveSiblingSetKeyCandidates()` and a new
   `warmSiblingCells()` that lazily `await loadCatalogCell()`s the
   destination cell and every sibling candidate BEFORE the (necessarily
   synchronous) `classifyOne` call.
2. **Any-parallel/any-rung defect (defect 2).** The SPELLING and
   ISAUTO-DEFECT checks in `resolveDefectOrAcquire` only fired when
   auto/printRun matched on at least one axis, so a card backed at the SAME
   cardNumber but a DIFFERENT auto+printRun combination together (e.g. a
   serial-numbered relic parallel vs. a sale bucketed generic "Base") fell
   through to ACQUIRE despite the checklist row existing one parallel/insert
   segment over. Fixed by adding a widest same-setKey check: ANY
   namesAgree-gated backed row at the same cardNumber, regardless of
   auto/printRun/parallel, now classifies as SPELLING. This also subsumes the
   "ad-hoc derived parallel" class (e.g. a `parseHobbyIqCardId`-invented
   `image-variation`/`ssp-refractor`/`short-print` parallel slug standing in
   for the card's real checklist parallel name) — no separate allowlist
   needed.

A third, independent finding came from a live point-read trace against the
FULL (unsampled) 2025 bowmans-best base-parallel pool
(`C:/tmp/bb25_trace_1530/RESULT.md`, 2026-09-26): of 23,383 sales in the
prior #1/#2 ACQUIRE rows ("2025/bowmans-best/Base", 899 + 660 sales),
**98.98% were already checklist-backed** under an exact/isAuto-flipped/
sibling-key id — PRESENT 74.5%, ISAUTO-DEFECT 21.9%, KEY-DEFECT 2.6% (under
sibling key `bowman`), and the residual 1.0% ABSENT further fragmented into a
cardNumber-parse defect (bare "B25", 65 sales), a combined key+isAuto dual
defect (33 sales, present at `hiq:baseball:2025:bowman:b25-jp:base:auto`),
and mislabelled insert/autograph sections (BPA-/DA-/BMA-/QA-/TA-/BTA-
prefixes read as "Base", 133 sales) — **zero genuine acquisition-worthy
gaps**. The trace also found `foldIntoAggregate` read
`detail.cardNumber` while `classifyOne`'s STALE-NO-ROW branch only ever set
the nested `detail.identity.cardNumber`, so every STALE-NO-ROW-sourced
ACQUIRE row's `distinctCardNumbers` silently read 0 — also fixed in this
regeneration (`cardNumber` now falls back to `detail.identity?.cardNumber`).
